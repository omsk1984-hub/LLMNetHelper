# Документация LLMNetHelper

Ночной агент мониторинга: собирает факты из Loki и Prometheus, строит
детерминированную сводку, привлекает LLM для диагностики, при необходимости —
планирует и применяет правку кода в отдельной ветке.

## Карта документации

| Документ | Содержание |
|---|---|
| [architecture.md](architecture.md) | Слои проектов, поток выполнения, ключевые принципы |
| [agent-loop.md](agent-loop.md) | ReAct-цикл: схема шага, стратегии, протокол вызова инструментов, белый список прогона и чата |
| [configuration.md](configuration.md) | Все опции, маппинг переменных окружения в секции, приоритеты |
| [runbook.md](runbook.md) | Запуск, режимы раннера, коды возврата, типовая диагностика |
| [deployment.md](deployment.md) | Развёртывание на хосте и в Docker, отличия конфигурации |

## Как читать эти файлы агенту

Каталог `docs/` подключён к агенту как источник контекста
(`Context:Sources:local-folder`, только `**/*.md`). Релевантные фрагменты
попадают в системный промпт по BM25-ранжированию относительно сводки ошибок.

Требования к содержанию здесь иные, чем в обычной документации:

- факты короткими предложениями, без длинных вступлений;
- устойчивая терминология (одно понятие — один термин во всех файлах);
- каждый раздел самодостаточен: фрагмент, извлечённый по chunk-size,
  должен читаться без соседних абзацев;
- никаких ссылок на содержимое вне репозитория.

## Статус проекта

Репозиторий автономен: не зависит от других репозиториев и внешних решений.
Все пути в конфигурации разрешаются от корня репозитория.
Исторические документы, описывающие происхождение проекта из другого
репозитория, находятся в `plans/` и помечены как архивные.
