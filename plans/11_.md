## 1. Диагностика: измерение baseline

Прежде чем оптимизировать — нужно понять, куда уходят токены.

### Что измерять

| Компонент | Как измерить | Целевое значение |
|-----------|--------------|------------------|
| System prompt | Длина в токенах | < 1000 |
| Chat history | Сумма токенов всех сообщений | < 4000 |
| Tool outputs | % от общего контекста | < 20% |
| Repo context | Токены на код/файлы | < 3000 |

### Инструменты

```python
import tiktoken

def count_tokens(text: str, model: str = "gpt-4") -> int:
    enc = tiktoken.encoding_for_model(model)
    return len(enc.encode(text))

def analyze_context(messages: list[dict]) -> dict:
    """Анализ распределения токенов в контексте"""
    total = 0
    breakdown = {}
    
    for msg in messages:
        role = msg["role"]
        tokens = count_tokens(msg["content"])
        total += tokens
        breakdown[role] = breakdown.get(role, 0) + tokens
    
    return {
        "total_tokens": total,
        "breakdown": breakdown,
        "tool_output_share": breakdown.get("tool", 0) / total * 100
    }
```

**Действие**: запустить анализ перед каждым запросом к модели в течение 1 недели, собрать статистику.

## 2. Техника 1: Sliding Window для истории

**Принцип**: хранить полные данные только для последних N ходов, остальное — сжимать или удалять.

### Реализация

```python
def sliding_window(messages: list[dict], keep_last: int = 2) -> list[dict]:
    """
    Оставляет system prompt + последние N пар user/assistant/tool.
    
    Args:
        messages: полная история чата
        keep_last: сколько последних ходов оставить нетронутыми
    """
    # Разделяем system и остальные сообщения
    system_msgs = [m for m in messages if m["role"] == "system"]
    other_msgs = [m for m in messages if m["role"] != "system"]
    
    # Оставляем только последние N*3 сообщений (user + assistant + tool)
    recent = other_msgs[-(keep_last * 3):]
    
    return system_msgs + recent
```

### Когда применять

- ✅ Длинные сессии (> 10 ходов)
- ✅ Агент читает много файлов
- ❌ Критична память о ранних решениях (используйте суммаризацию вместо удаления)

## 3. Техника 2: Truncation tool outputs

**Принцип**: ограничивать размер вывода инструментов, оставляя начало и конец.

### Реализация

```python
def truncate_tool_output(content: str, max_chars: int = 2000) -> str:
    """
    Обрезает длинный вывод, сохраняя начало и конец.
    
    Пример:
        Input:  "line1\nline2\n...\nline1000" (10000 chars)
        Output: "line1\nline2\n...\n[... 8000 chars truncated ...]\nline999\nline1000"
    """
    if len(content) <= max_chars:
        return content
    
    head_size = max_chars // 2
    tail_size = max_chars // 2
    
    head = content[:head_size]
    tail = content[-tail_size:]
    truncated = len(content) - head_size - tail_size
    
    return f"{head}\n\n[... {truncated} chars truncated ...]\n\n{tail}"

def apply_truncation(messages: list[dict], max_chars: int = 2000) -> list[dict]:
    """Применяет обрезку ко всем tool-сообщениям"""
    result = []
    for msg in messages:
        if msg["role"] == "tool":
            msg_copy = msg.copy()
            msg_copy["content"] = truncate_tool_output(msg["content"], max_chars)
            result.append(msg_copy)
        else:
            result.append(msg)
    return result
```

### Параметры

| Параметр | Рекомендация |
|----------|--------------|
| `max_chars` для `read_file` | 2000–4000 |
| `max_chars` для `bash`/`terminal` | 1500–3000 |
| `max_chars` для `grep`/`search` | 1000–2000 |

## 4. Техника 3: Summarization старых ходов

**Принцип**: заменять старые tool outputs на краткое резюме через LLM.

### Реализация

```python
from openai import OpenAI

client = OpenAI()

def summarize_tool_output(tool_name: str, output: str) -> str:
    """Генерирует 1-строчное резюме вывода инструмента"""
    prompt = f"""Суммаризируй вывод инструмента {tool_name} в одно предложение.
Укажи: что было найдено/выполнено, ключевые детали.

Вывод:
{output[:3000]}

Резюме:"""
    
    response = client.chat.completions.create(
        model="gpt-4o-mini",  # дешёвая модель для суммаризации
        messages=[{"role": "user", "content": prompt}],
        max_tokens=100
    )
    return response.choices[0].message.content

def compress_old_turns(
    messages: list[dict], 
    keep_full_for_last: int = 1
) -> list[dict]:
    """
    Сжимает старые tool outputs в резюме.
    
    Args:
        messages: полная история
        keep_full_for_last: для скольких последних ходов оставить полные данные
    """
    # Находим индексы tool-сообщений
    tool_indices = [i for i, m in enumerate(messages) if m["role"] == "tool"]
    
    # Определяем, какие нужно сжать (все, кроме последних N)
    indices_to_compress = tool_indices[:-keep_full_for_last * 2]
    
    result = messages.copy()
    for idx in indices_to_compress:
        msg = result[idx]
        tool_name = msg.get("name", "unknown")
        summary = summarize_tool_output(tool_name, msg["content"])
        result[idx] = {
            "role": "tool",
            "name": tool_name,
            "content": f"[Summary: {summary}]"
        }
    
    return result
```

### Когда применять

- ✅ Очень длинные сессии (> 20 ходов)
- ✅ Агент работает над сложной многошаговой задачей
- ⚠️ Требует дополнительных вызовов LLM (но дешевле, чем тащить большой контекст)

## 5. Техника 4: Repo-map вместо полного кода

**Принцип**: хранить в контексте скелет репозитория (сигнатуры функций/классов), а не полный код.

### Генерация repo-map

```python
import ast
from pathlib import Path

def generate_repo_map(repo_path: str) -> str:
    """
    Генерирует скелет репозитория: только имена файлов, классов, функций.
    
    Пример вывода:
    src/
    ├── main.py
    │   ├── class App
    │   │   ├── def run()
    │   │   └── def shutdown()
    │   └── class Config
    └── utils/
        └── helpers.py
            └── def parse_args()
    """
    result = []
    
    for py_file in Path(repo_path).rglob("*.py"):
        rel_path = py_file.relative_to(repo_path)
        result.append(f"{rel_path}")
        
        try:
            with open(py_file) as f:
                tree = ast.parse(f.read())
            
            for node in ast.walk(tree):
                if isinstance(node, ast.ClassDef):
                    result.append(f"  ├── class {node.name}")
                    for item in node.body:
                        if isinstance(item, ast.FunctionDef):
                            args = ", ".join(arg.arg for arg in item.args.args if arg.arg != "self")
                            result.append(f"  │   ├── def {item.name}({args})")
                elif isinstance(node, ast.FunctionDef) and not hasattr(node, "_parent"):
                    # Top-level функции
                    args = ", ".join(arg.arg for arg in node.args.args)
                    result.append(f"  └── def {node.name}({args})")
        except:
            pass
    
    return "\n".join(result)
```

### Интеграция в контекст

```python
def build_context_with_repo_map(user_query: str, repo_path: str) -> list[dict]:
    repo_map = generate_repo_map(repo_path)
    
    return [
        {
            "role": "system",
            "content": f"Ты — AI-ассистент для кодинга.\n\nСтруктура проекта:\n{repo_map}\n\nИспользуй эту структуру для навигации. Читай файлы по мере необходимости."
        },
        {
            "role": "user",
            "content": user_query
        }
    ]
```

### Преимущества

- **Экономия**: ~500 токенов вместо 10 000+ на полный код
- **Навигация**: модель понимает структуру и может целенаправленно читать нужные файлы
- **Актуальность**: repo-map можно кэшировать и обновлять только при изменении структуры

## 8. Техника 7: Model Routing

**Принцип**: использовать разные модели для разных типов задач.

### Реализация

```python
def select_model(task: str, context_size: int) -> str:
    """
    Выбирает модель в зависимости от сложности задачи и размера контекста.
    """
    # Простые задачи → дешёвая модель
    if len(task) < 200 and "объясни" in task.lower():
        return "gpt-4o-mini"
    
    # Большие контексты → модель с длинным окном
    if context_size > 32000:
        return "claude-3-5-sonnet-20241022"  # 200k context
    
    # Код → специализированная модель
    if any(kw in task.lower() for kw in ["код", "функция", "класс", "debug"]):
        return "deepseek-coder"
    
    # Сложные задачи → мощная модель
    return "gpt-4o"

def route_and_execute(task: str, messages: list[dict]) -> str:
    model = select_model(task, sum(len(m["content"]) for m in messages))
    
    client = OpenAI()
    response = client.chat.completions.create(
        model=model,
        messages=messages
    )
    
    return response.choices[0].message.content
```

### Матрица маршрутизации

| Тип задачи | Модель | Стоимость |
|------------|--------|-----------|
| Простые вопросы | gpt-4o-mini / DeepSeek-V3-Lite | $0.15/M tokens |
| Код (чтение/понимание) | DeepSeek-Coder | $0.14/M tokens |
| Код (генерация) | gpt-4o / Claude Sonnet | $3–5/M tokens |
| Сложные рассуждения | o1 / Claude Opus | $15/M tokens |

## 9. Готовая реализация: LLM-прокси

**Принцип**: поднять локальный прокси, который перехватывает запросы и применяет все оптимизации.

### Архитектура

```
[AI-агент] → [LLM-прокси] → [OpenAI/DeepSeek/Claude API]
                  ↓
            - Sliding window
            - Truncation
            - Summarization
            - Model routing
            - Caching
```

### Реализация на FastAPI

```python
from fastapi import FastAPI, Request
from pydantic import BaseModel
import httpx

app = FastAPI()

class ChatRequest(BaseModel):
    model: str
    messages: list[dict]
    **kwargs

@app.post("/v1/chat/completions")
async def chat_completions(request: ChatRequest):
    # 1. Применяем sliding window
    messages = sliding_window(request.messages, keep_last=2)
    
    # 2. Обрезаем tool outputs
    messages = apply_truncation(messages, max_chars=2000)
    
    # 3. Сжимаем старые ходы (опционально)
    if len(messages) > 10:
        messages = compress_old_turns(messages, keep_full_for_last=1)
    
    # 4. Model routing
    task = messages[-1]["content"]
    model = select_model(task, sum(len(m["content"]) for m in messages))
    
    # 5. Отправляем в API
    async with httpx.AsyncClient() as client:
        response = await client.post(
            "https://api.openai.com/v1/chat/completions",
            headers={"Authorization": f"Bearer {OPENAI_API_KEY}"},
            json={"model": model, "messages": messages, **request.kwargs}
        )
    
    return response.json()
```
