# Ночной агент для проверки Loki и Prometheus

## Коротко: стоит ли создавать консольную утилиту?

**Да, но не "чистую" консольку, а .NET Worker Service с возможностью ручного запуска через консоль.** Вот почему:

- Консольная утилита, запускаемая внешним `cron` раз в сутки — простейший вариант, но у неё нет встроенной логики повторных запусков, graceful shutdown, health checks, graceful retry [[1]].
- Worker Service (.NET 8) даёт вам DI, логирование через `ILogger`, конфигурацию из `appsettings.json`/переменных окружения, жизненный цикл приложения и Quartz.NET/Hangfire для планирования.
- Docker отлично умеет запускать Worker Service как долгоживущий контейнер.

При этом Worker Service можно **запустить и однократно через консоль** с аргументами (`--run-now`), поэтому вы получаете лучшее из двух миров.

## Пошаговый план реализации

### 1. Определение scope (что именно проверять)

Составьте чек-лист, иначе агент будет делать "что-то непонятное":

**Для Loki (логи):**
- Топ-20 самых частых ошибок за сутки (по лейблам `level=error`)
- Новые паттерны ошибок, которых не было вчера (diff)
- Сервисы с аномально высоким ростом количества логов
- Логи с уровнями `fatal`/`critical` — всегда в отчёт
- Ошибки подключения к БД, таймауты, `OutOfMemoryException`

**Для Prometheus (метрики):**
- `rate(http_requests_total{code=~"5.."}[5m])` — рост 5xx
- `process_resident_memory_bytes` — рост потребления памяти
- `up == 0` — упавшие таргеты
- `rate(process_cpu_seconds_total[5m])` — аномалии CPU
- Сработавшие alerting rules за сутки (API `/api/v1/rules`)
- `node_filesystem_avail_bytes` — заканчивающееся место

### 4. Ключевые реализации

**`Program.cs` (главное):**

```csharp
var builder = Host.CreateApplicationBuilder(args);

builder.Services.AddHttpClient("loki", c =>
    c.BaseAddress = new Uri(builder.Configuration["Loki:Url"]!));
builder.Services.AddHttpClient("prometheus", c =>
    c.BaseAddress = new Uri(builder.Configuration["Prometheus:Url"]!));

builder.Services.AddTransient<ILokiCollector, LokiCollector>();
builder.Services.AddTransient<IPrometheusCollector, PrometheusCollector>();
builder.Services.AddTransient<IReportAnalyzer, LlmAnalyzer>();
builder.Services.AddTransient<INotifier, TelegramNotifier>();

builder.Services.AddQuartz(q =>
{
    var jobKey = new JobKey("nightly-check");
    q.AddJob<NightlyCheckJob>(opts => opts.WithIdentity(jobKey));
    q.AddTrigger(opts => opts
        .ForJob(jobKey)
        .WithIdentity("nightly-trigger")
        .WithCronSchedule(builder.Configuration["Schedule:Cron"] ?? "0 0 2 * * ?")); // 02:00 каждый день
});
builder.Services.AddQuartzHostedService(q => q.WaitForJobsToComplete = true);

builder.Services.AddHostedService<Worker>();
builder.Host.UseSerilog((_, lc) => lc.WriteTo.Console());

var host = builder.Build();

// Возможность ручного запуска: --run-now
if (args.Contains("--run-now"))
{
    using var scope = host.Services.CreateScope();
    await scope.ServiceProvider.GetRequiredService<NightlyCheckJob>().ExecuteAsync();
    return;
}

await host.RunAsync();
```

**`NightlyCheckJob.cs` (основной flow):**

```csharp
public class NightlyCheckJob(
    ILokiCollector loki,
    IPrometheusCollector prometheus,
    IReportAnalyzer analyzer,
    INotifier notifier,
    ILogger<NightlyCheckJob> logger) : IJob
{
    public async Task Execute(IJobExecutionContext context)
    {
        try
        {
            var window = DateTimeOffset.UtcNow.AddDays(-1);
            
            // 1. Сбор
            var lokiErrors = await loki.GetErrorsAsync(window, DateTimeOffset.UtcNow);
            var prometheusAlerts = await prometheus.GetFiredAlertsAsync(window, DateTimeOffset.UtcNow);
            var metrics = await prometheus.GetAnomalousMetricsAsync(window, DateTimeOffset.UtcNow);

            // 2. Анализ (правила + LLM)
            var report = await analyzer.AnalyzeAsync(new ReportInput
            {
                LokiErrors = lokiErrors,
                Alerts = prometheusAlerts,
                Metrics = metrics,
                Period = (window, DateTimeOffset.UtcNow)
            });

            // 3. Рендер и отправка
            var markdown = MarkdownReportRenderer.Render(report);
            await notifier.SendAsync(markdown);

            logger.LogInformation("Nightly check completed. Issues found: {Count}", report.Issues.Count);
        }
        catch (Exception ex)
        {
            logger.LogError(ex, "Nightly check failed");
            throw; // чтобы Quartz залогировал failure
        }
    }
}
```

**`LokiCollector.cs` (пример запроса):**

```csharp
public async Task<IReadOnlyList<LokiEntry>> GetErrorsAsync(DateTimeOffset from, DateTimeOffset to)
{
    // LogQL: {app=~".+"} |= `` | logfmt | level =~ "error|fatal|critical"
    var query = HttpUtility.ParseQueryString(string.Empty);
    query["query"] = "{app=~\".+\"} | level =~ \"error|fatal|critical\"";
    query["start"] = from.ToUnixTimeSeconds().ToString();
    query["end"]   = to.ToUnixTimeSeconds().ToString();
    query["limit"] = "1000";

    using var response = await _http.GetAsync($"/loki/api/v1/query_range?{query}");
    response.EnsureSuccessStatusCode();
    // ... десериализация JSON
}
```

**LLM-анализ (Semantic Kernel):**

Именно LLM даёт "рекомендации по устранению". Простые правила найдут только шаблонные проблемы.

```csharp
public class LlmAnalyzer(IKernel kernel) : IReportAnalyzer
{
    public async Task<NightlyReport> AnalyzeAsync(ReportInput input)
    {
        var prompt = $"""
            Ты — SRE-ассистент. Проанализируй ошибки из Loki и метрики из Prometheus за сутки.
            Сформируй отчёт по секциям:
            1. Критические проблемы (с конкретными сервисами и ошибками)
            2. Тренды и аномалии
            3. Конкретные рекомендации по устранению с шагами
            4. Игнорируемые ошибки (шум)
            
            ДАННЫЕ:
            Логи: {Serialize(input.LokiErrors)}
            Алерты: {Serialize(input.Alerts)}
            Метрики: {Serialize(input.Metrics)}
            """;

        var result = await kernel.InvokePromptAsync(prompt);
        return ParseReport(result.ToString());
    }
}
```

### 6. Запуск именно на WSL

Нюансы WSL:

1. **Доступ к Loki/Prometheus.** Если они на хосте Windows, а агент в WSL — используйте `host.docker.internal` из контейнера (работает и в Docker Desktop для Windows с WSL2 backend).
2. **Cron не нужен** — Quartz.NET внутри контейнера сам планирует. Cron имеет смысл только если вы запускаете *чистую консольку* один раз, но мы уже выбрали Worker Service.
3. **Перезагрузка WSL** — убедитесь, что Docker Engine в WSL2 стартует автоматически при входе в Windows (`wsl --user -d <distro>` в автозагрузке или в Startup-скриптах Windows).
4. **Автозапуск контейнера** — `restart: unless-stopped` в compose гарантирует, что агент поднимется после рестарта Docker.

### 7. Отчёты: куда слать

| Канал | Когда подходит |
|---|---|
| Telegram bot (через `Telegram.Bot`) | Самый простой, работает из любой сети, push-нотификации |
| Slack webhook | Если команда уже живёт в Slack |
| Email (MailKit / SMTP) | Если нужен формальный отчёт для руководства |
| Сохранение в S3/MinIO + ссылка | Большой объём, аудит |
| Post в Grafana (через annotation API) | Привязка отчёта к таймлайну метрик |

Рекомендую **Telegram + архив в S3**: быстрый пуш + история.

## Готовые альтернативы (стоит рассмотреть перед написанием своего)

Раз уж вы спрашиваете "стоит ли создавать", честно скажу — часть функционала уже есть в открытых проектах:

- **NudgeBee** — self-hosted AI SRE copilot, интегрируется с Prometheus и Loki [[4]]
- **Hyground** — AI SRE агент для Европы (Kubernetes, Prometheus, Loki) [[8]]
- **Sherlog-prometheus-agent** — LLM-агент для PromQL запросов на естественном языке [[10]]
- **incident-agent** — подключается к Prometheus + Loki и умеет реагировать на инциденты [[5]]

Если вам нужен именно **ночной отчёт с рекомендациями**, а не реактивный SRE — своё решение будет более гибким и точно под ваши метрики. Но если цель — быстро получить SRE-ассистента, стоит сначала потестить одно из готовых решений, а затем при необходимости написать свой Worker Service.
