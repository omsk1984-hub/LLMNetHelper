Да, создание консольной утилиты — это **отличное и архитектурно верное решение** для такой задачи. Учитывая ваш опыт с .NET 8 и C# 12, легковесное консольное приложение (или Worker Service) будет идеальным выбором: оно быстро запускается, потребляет минимум ресурсов, легко контейнеризируется и позволяет использовать знакомый вам стек (HttpClient, System.Text.Json, LINQ).

Запуск этого сервиса в Docker на WSL2 — также правильный подход, так как это изолирует окружение и гарантирует идентичность поведения на любом хосте.

Ниже представлен подробный пошаговый план реализации.

---

### Шаг 1: Архитектура решения
1. **Тип приложения**: .NET 8 Console Application (с использованием Top-level statements для лаконичности). Приложение выполняет проверку, формирует отчет и завершает работу (exit code 0 при успехе). Это лучше, чем постоянно висящий в памяти Worker, так как позволяет запускать его строго по расписанию и гарантированно освобождать ресурсы.
2. **Источники данных**: HTTP API Prometheus (`/api/v1/query`) и Loki (`/loki/api/v1/query_range`).
3. **Хранение отчета**: Локальный файл (Markdown/HTML) в примонтированной Docker-папке + опционально отправка в Telegram/Slack/Email.
4. **Оркестрация**: Windows Task Scheduler вызывает команду `wsl -d <дистрибутив> docker run --rm ...`, что надежнее, чем встроенный `cron` в WSL (который часто "отваливается" после спящего режима Windows).

cd MonitoringAgent

### Шаг 3: Реализация логики на C# 12
Используйте современные возможности C# (records, top-level statements, primary constructors).

**Файл `Program.cs`:**
```csharp
using System.Net.Http.Json;
using System.Text.Json;

var prometheusUrl = Environment.GetEnvironmentVariable("PROMETHEUS_URL") ?? "http://host.docker.internal:9090";
var lokiUrl = Environment.GetEnvironmentVariable("LOKI_URL") ?? "http://host.docker.internal:3100";
var reportPath = Environment.GetEnvironmentVariable("REPORT_PATH") ?? "/app/reports";

using var httpClient = new HttpClient { Timeout = TimeSpan.FromSeconds(10) };

var report = new System.Text.StringBuilder();
report.AppendLine($"# Отчет по мониторингу\n**Дата:** {DateTime.UtcNow:yyyy-MM-dd HH:mm:ss} UTC\n");

// 1. Проверка Prometheus: ищем упавшие таргеты (up == 0)
try
{
    var query = Uri.EscapeDataString("up == 0");
    var response = await httpClient.GetFromJsonAsync<PrometheusResponse>($"{prometheusUrl}/api/v1/query?query={query}");
    
    if (response?.Data.Result.Count > 0)
    {
        report.AppendLine("### 🔴 Ошибки Prometheus (Недоступные таргеты):");
        foreach (var metric in response.Data.Result)
        {
            var job = metric.Metric.TryGetValue("job", out var j) ? j : "unknown";
            var instance = metric.Metric.TryGetValue("instance", out var i) ? i : "unknown";
            report.AppendLine($"- **{job}** на `{instance}` не отвечает.");
        }
        report.AppendLine("**Рекомендация:** Проверьте доступность сети, логи контейнеров и статус systemd-сервисов на указанных хостах.\n");
    }
    else
    {
        report.AppendLine("### 🟢 Prometheus: Все таргеты активны.\n");
    }
}
catch (Exception ex)
{
    report.AppendLine($"### ⚠️ Ошибка опроса Prometheus: {ex.Message}\n");
}

// 2. Проверка Loki: ищем ошибки (level="error" или "exception") за последние 24 часа
try
{
    var endTime = DateTimeOffset.UtcNow.ToUnixTimeSeconds();
    var startTime = endTime - 86400; // 24 часа назад
    var logQuery = Uri.EscapeDataString("sum(count_over_time({level=\"error\"} |~ \"(?i)exception|fail|error\" [24h])) by (job)");
    
    var response = await httpClient.GetFromJsonAsync<LokiResponse>($"{lokiUrl}/loki/api/v1/query?query={logQuery}&time={endTime}");
    
    if (response?.Data.Result.Count > 0)
    {
        report.AppendLine("### 🔴 Ошибки в логах (Loki, за 24ч):");
        foreach (var stream in response.Data.Result)
        {
            var job = stream.Stream.TryGetValue("job", out var j) ? j : "unknown";
            var count = stream.Value[1]; // [timestamp, value]
            report.AppendLine($"- **{job}**: {count} ошибок.");
        }
        report.AppendLine("**Рекомендация:** Изучите детальные логи в Grafana по указанным job за последние 24 часа, обратите внимание на трассировки исключений.\n");
    }
    else
    {
        report.AppendLine("### 🟢 Loki: Критических ошибок в логах не обнаружено.\n");
    }
}
catch (Exception ex)
{
    report.AppendLine($"### ⚠️ Ошибка опроса Loki: {ex.Message}\n");
}

// 3. Сохранение отчета
Directory.CreateDirectory(reportPath);
var fileName = $"report_{DateTime.UtcNow:yyyyMMdd_HHmmss}.md";
var fullPath = Path.Combine(reportPath, fileName);
await File.WriteAllTextAsync(fullPath, report.ToString());
Console.WriteLine($"Отчет успешно сохранен: {fullPath}");

// --- Модели для десериализации ---
record PrometheusResponse(string status, PrometheusData Data);
record PrometheusData(List<PrometheusResult> Result);
record PrometheusResult(Dictionary<string, string> Metric, string Value);

record LokiResponse(string status, LokiData Data);
record LokiData(List<LokiResult> Result);
record LokiResult(Dictionary<string, string> Stream, List<string> Value);
```
*Примечание:* `host.docker.internal` используется для доступа к сервисам, запущенным на хост-машине Windows/WSL из контейнера. В Docker Desktop на WSL2 это работает из коробки.

### Шаг 4: Контейнеризация (Docker)
Создайте `Dockerfile` с использованием многоступенчатой сборки для минимального размера образа:

```dockerfile
# Build stage
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish -c Release -o /app --no-restore

# Runtime stage
FROM mcr.microsoft.com/dotnet/runtime:8.0 AS runtime
WORKDIR /app
COPY --from=build /app .
# Создаем пользователя без прав root для безопасности
RUN useradd -m monitoruser && chown -R monitoruser:monitoruser /app
USER monitoruser
ENTRYPOINT ["dotnet", "MonitoringAgent.dll"]
```

Создайте `docker-compose.yml` для удобства управления (опционально, но полезно для монтирования томов):

```yaml
services:
  monitoring-agent:
    build: .
    container_name: monitoring-agent
    environment:
      - PROMETHEUS_URL=http://host.docker.internal:9090
      - LOKI_URL=http://host.docker.internal:3100
      - REPORT_PATH=/app/reports
    volumes:
      - ./reports:/app/reports
    # Команда ниже нужна только если вы используете docker-compose up, 
    # но для разовых запусков лучше использовать docker run --rm
```

### Шаг 5: Настройка расписания в WSL (Надежный способ)
**Важно:** Демон `cron` в WSL2 часто останавливается при переходе Windows в спящий режим или при перезагрузке. Самый надежный способ запускать Docker-контейнер по расписанию в среде WSL — использовать **Планировщик заданий Windows (Task Scheduler)**.

1. Откройте **Планировщик заданий** в Windows.
2. Создайте новую задачу:
   - **Имя**: `Run Monitoring Agent`
   - **Триггер**: Ежедневно, например, в 03:00 ночи.
   - **Действие**: Запуск программы.
   - **Программа или сценарий**: `wsl.exe`
   - **Аргументы**: `-d Ubuntu -e docker run --rm -v "C:\путь\к\вашему\проекту\reports:/app/reports" monitoring-agent` *(замените `Ubuntu` на имя вашего дистрибутива WSL, если оно отличается, и укажите правильный путь к папке отчетов)*.
   - **Дополнительно**: В настройках задачи поставьте галочку "Выполнять вне зависимости от регистрации пользователя" и "Выполнять с наивысшими правами".

*Альтернатива*: Если вы хотите использовать именно `cron` внутри WSL, вам потребуется настроить скрипт инициализации (например, через `/etc/wsl.conf` и задачу Windows, запускающую `service cron start` при входе в систему), но метод с прямым вызовом `wsl -e docker run` через Планировщик значительно проще и надежнее.

### Шаг 6: Улучшение рекомендаций и алертинга (Рекомендации на будущее)
1. **Отправка в Telegram**: Добавьте в проект `Telegram.Bot` или простой `HttpClient` POST-запрос к API Telegram, чтобы отправлять сформированный Markdown-отчет в ваш личный чат или чат команды. Это сделает отчеты мгновенно доступными.
2. **Статус-коды и алерты**: Вместо простого поиска строк, используйте встроенные правила (Rules) Prometheus. Запрос `ALERTS{alertstate="firing"}` сразу вернет все активные алерты, что гораздо надежнее, чем парсить сырые метрики.
3. **История отчетов**: Настройте в `docker-compose.yml` или через скрипт автоматическое удаление отчетов старше 30 дней, чтобы не засорять диск: `find /app/reports -type f -mtime +30 -delete`.

- Использует ваш основной стек (.NET 8, C# 12, Docker), не требуя изучения Python или Bash-скриптинга на глубоком уровне.
